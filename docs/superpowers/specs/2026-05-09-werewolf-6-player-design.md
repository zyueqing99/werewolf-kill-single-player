# 单机版狼人杀 6 人局第一版设计

## 背景

本项目第一版要实现一个本地运行的单机狼人杀 Web App。用户在浏览器里参与一局 6 人狼人杀，其中用户本人随机扮演一个角色，其余 5 名玩家由 AI agent 控制。第一版目标是完成一局可玩的闭环，而不是一次性覆盖完整狼人杀角色池和联网多人能力。

## 第一版范围

第一版固定为 6 人局：

- 2 名狼人
- 1 名预言家
- 1 名女巫
- 2 名村民

玩家结构：

- 1 名真人玩家
- 5 名 AI agent

身份分配：

- 开局随机分配全部角色
- 真人玩家也随机获得身份

运行方式：

- 本地启动前端和后端服务
- 浏览器访问本地 Web App 进行游戏
- 使用 OpenAI 兼容 API 驱动 AI agent

第一版不包含：

- 联网多人
- 账号系统
- 数据库存档
- 警长、遗言、竞选、守卫、猎人、白痴等扩展规则
- 完整桌面端打包
- 长期跨局记忆

## 推荐技术路线

采用本地 Web App 架构：

- 前端：React + TypeScript + Vite
- 后端：Node.js + TypeScript + Fastify
- 实时通信：WebSocket
- 模型接入：OpenAI 兼容 API

后端是权威状态源，负责所有规则判断、状态推进、夜间结算、投票结算、胜负判断、AI prompt 构造和模型调用。前端只展示真人玩家当前可见的信息，并提交真人玩家操作。

模型配置通过环境变量提供：

- API base URL
- API key
- model name

这样后续可以替换为其他 OpenAI 兼容服务，例如本地模型网关、Ollama 或 LM Studio 等。

## 核心模块

### 前端模块

前端提供单页游戏界面，偏群聊软件体验：

- 玩家列表：展示 6 名玩家、存活状态、出局状态和公开身份信息
- 群聊消息流：展示系统消息、AI 发言、真人发言、死亡公告、投票结果
- 当前阶段提示：展示白天、夜晚、发言、投票、结算等阶段
- 操作面板：根据真人玩家当前可执行动作展示输入框、按钮或目标选择器
- 身份提示：展示真人玩家身份和剩余能力，例如女巫解药、毒药状态

前端不直接计算规则，不保存上帝视角，不暴露其他玩家私密信息。

### 后端游戏引擎

游戏引擎负责：

- 创建游戏
- 随机分配角色
- 管理玩家状态
- 推进阶段
- 校验操作是否合法
- 结算夜间行动
- 结算白天投票
- 判断胜负
- 生成前端可见状态
- 生成 agent 可见状态

游戏引擎应作为纯业务核心实现，尽量减少对 Web 框架和模型 API 的直接依赖，方便单元测试。

### Agent 层

每个 AI agent 拥有：

- 固定人设：名字、说话风格、谨慎程度、攻击性、带节奏倾向等
- 私有信息：自己的身份、狼人队友、预言家查验结果、女巫药品状态
- 公开信息：公开发言、死亡公告、投票结果、当前轮次、当前阶段

AI agent 不能直接修改游戏状态。模型只能返回结构化决策，由后端校验并应用。

Agent 需要支持以下任务：

- 白天发言：返回自然语言发言
- 狼人夜间行动：返回击杀目标
- 预言家查验：返回查验目标
- 女巫行动：返回是否使用解药、是否使用毒药、毒杀目标
- 白天投票：返回投票目标或弃票

模型输出优先要求 JSON。若模型输出无法解析、目标非法或动作不符合当前阶段，后端使用保底策略兜底，避免对局卡死。

## 对局流程

### 1. 开局

后端创建 6 名玩家并随机分配身份。真人玩家看到自己的身份。狼人玩家能看到狼队友。其他身份只看到自己的身份。

### 2. 夜晚

夜晚行动按顺序处理：

1. 狼人选择击杀目标
2. 预言家选择查验目标，并得到好人或狼人结果
3. 女巫看到当晚被杀目标，可选择是否使用解药；若毒药仍可用，也可选择是否毒杀一名玩家

第一版夜间行动由当前身份对应玩家执行：

- 若真人是对应角色，则前端显示操作面板
- 若 AI 是对应角色，则后端调用 agent 决策

### 3. 天亮

系统公布昨夜死亡情况。若无人死亡，公布平安夜。

### 4. 白天发言

存活玩家按顺序发言。真人玩家轮到时输入发言，AI agent 轮到时由模型生成发言。

### 5. 投票

所有存活玩家投票放逐一名玩家，也可以弃票。真人玩家手动投票，AI agent 根据自身视角和公开信息决策。

### 6. 放逐结算

得票最高者出局。第一版采用简单平票规则：若最高票平票，则无人出局。

### 7. 胜负判断

每次夜间结算和放逐结算后检查胜负：

- 狼人全灭：好人胜利
- 狼人人数大于等于好人人数：狼人胜利
- 否则进入下一阶段

## 数据流

前端通过 HTTP 或 WebSocket 发起操作：

- startGame
- submitDaySpeech
- submitVote
- submitNightAction
- requestNext

后端处理动作后推进状态机，并通过 WebSocket 推送新的前端可见状态。

前端可见状态只包含：

- 真人玩家自己的身份和能力状态
- 公开消息
- 公开玩家状态
- 当前阶段
- 当前可执行动作
- 游戏胜负结果

后端内部状态额外包含：

- 所有玩家真实身份
- 所有私密行动
- AI 私有记忆
- 夜间临时结算信息
- 调试日志

## 信息隔离

信息隔离是第一版的核心要求。不同视角看到的信息不同：

- 真人玩家只能看到自己身份和公开信息
- 狼人 agent 能看到狼队友
- 预言家 agent 能看到自己的查验结果
- 女巫 agent 能看到药品状态和当晚被杀目标
- 村民 agent 只能看到公开信息和自己的村民身份

构造 prompt 时必须从后端状态中提取该 agent 的可见切片，不能把完整游戏状态直接传给模型。

## 错误处理

第一版需要保证模型异常不会卡死对局：

- JSON 解析失败：重试一次，仍失败则使用保底策略
- 目标不存在：选择合法目标或弃权
- 目标已死亡：选择合法目标或弃权
- 当前阶段不允许该动作：拒绝动作并记录日志
- 重复提交：忽略后续提交并返回当前状态
- 模型请求失败：使用保底策略并记录错误

保底策略应简单、可预测：

- 发言失败：生成一条短系统代发言，例如“我先听听大家怎么说。”
- 狼人行动失败：随机选择一名非狼人存活玩家
- 预言家行动失败：随机查验一名未查验存活玩家
- 女巫行动失败：默认不使用药
- 投票失败：弃票

## 测试策略

第一版测试重点放在后端规则引擎：

- 身份分配数量正确
- 真人玩家身份随机参与分配
- 狼人知道队友
- 非狼人不能看到狼人信息
- 夜晚击杀结算正确
- 女巫解药和毒药只可使用一次
- 预言家查验结果正确
- 投票放逐结算正确
- 平票无人出局
- 狼人全灭时好人胜利
- 狼人人数大于等于好人人数时狼人胜利
- 模型输出非法时对局不会卡死

前端测试第一版只覆盖关键交互：

- 能开始一局
- 能展示聊天消息
- 真人玩家轮到发言时能提交发言
- 真人玩家轮到投票时能提交投票
- 真人玩家为夜间角色时能提交夜间行动
- 游戏结束时能展示胜负结果

## 第一版验收标准

第一版完成时应满足：

- 能在本地浏览器中完整跑完一局 6 人狼人杀
- 真人玩家随机获得身份并参与对局
- 5 名 AI agent 能按各自视角发言、投票和执行夜间行动
- 后端不向前端暴露上帝视角
- 后端不向 agent prompt 暴露超出身份视角的信息
- 模型异常或格式错误不会导致游戏卡死
- 规则引擎有针对核心流程的自动化测试

## 未来扩展方向

第一版完成后可以扩展：

- 更多角色：猎人、守卫、白痴、骑士、丘比特等
- 更多人数配置：9 人局、12 人局
- 角色配置模板
- AI 性格编辑器
- 对局复盘
- 调试面板
- 本地存档
- Electron 桌面端打包
- 本地模型支持
- 观战模式和纯 AI 自动对局
